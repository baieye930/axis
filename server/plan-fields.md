# 날짜별 계획 저장 필드 (서버 확인 필요, 운영 반영 안 함)

앱이 날짜 기록(`day`)과 설정(`prefs`)에 새로 쓰는 필드다. 기존 필드는 그대로이고, 새 필드가 없는 예전 데이터도 정상 동작한다(마이그레이션 불필요).

## day (날짜별 기록, `axis_day_put` / `axis_days_get`)
| 필드 | 내용 |
|---|---|
| `sc` | 계획 정보. `w`(예상 기상, 시간 단위 소수), `st`(`"edit"` 수정 중 · `"saved"` 저장됨, 없으면 자동 초안), `ts`(저장 시각) |
| `adj` | 그날의 루틴 조정. `{항목id: {dt:분} \| {skip:true} \| {at:"HH:MM", len?:분} \| {dt, len}}` |
| `extra` | 그날의 약속 배열 `{id,t,at,to,memo,notify,v:2,shove:false}` (시계 시각, 04:00~다음날 04:00 안) |
| `extraOff` | 반복 약속을 그날만 뺀 목록 `{약속id:1}` |

- 미래 날짜는 `wake`를 만들지 않는다. 계획만 있는 행(`wake` 없음)이 생길 수 있으니 서버의 통계·집계가 `wake` 없는 행을 기록으로 세지 않는지 확인한다.
- 앱은 `data` JSON 전체를 그대로 보낸다. **RPC나 테이블이 알려진 키만 저장(화이트리스트)한다면 위 4개 키를 허용해야 한다.** 이 저장소에서는 서버 동작을 확인할 수 없다.

## prefs (설정, 기존 prefs 동기화)
| 필드 | 내용 |
|---|---|
| `tone` | 알림 말투 `soft`(기본) · `polite` · `brief` |
| `extra` | 반복 약속 배열 `{…약속 필드, rep:"daily"|"weekdays"|"days", dows?:[0-6], from:"YYYY-MM-DD"}` |

## 확인 절차 (적용 전, 운영 반영 금지)
1. 스테이징 프로젝트에서 위 필드를 포함한 `axis_day_put`/prefs 저장 후 `axis_days_get`으로 그대로 돌아오는지 확인한다.
2. 돌아오지 않으면 해당 RPC의 허용 키 목록에 추가하는 마이그레이션을 작성한다(스키마를 본 뒤 작성).
3. 잠금 화면 푸시가 `adj`·`extra`·`sc`를 읽게 하는 작업은 `server/README.md` 참고.
