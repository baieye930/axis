# 잠금 화면 푸시에 알림 말투 적용하기 (서버 작업, 아직 적용 안 됨)

이 저장소(GitHub Pages 앱)에는 푸시를 보내는 서버 코드가 없다. 앱은 `axis_push_subscribe` RPC로 기기 구독만 등록하고,
정해진 시각에 오는 잠금 화면 알림의 **제목·본문은 서버(Supabase 쪽 스케줄러/Edge Function, 앱의 `PUSH_URL`)가 완성해서 보낸다.**
앱은 그 문구를 만들거나 바꿀 수 없다. 그래서 알림 말투는 지금 **화면 알림·다른 탭 알림·운동 휴식/루틴 타이머 안내**에만 적용돼 있고,
잠금 화면 푸시는 서버를 고치기 전까지 기존 문구 그대로다.

## 앱이 이미 해 둔 것
- `prefs.tone`(`soft` 기본 | `polite` | `brief`)을 설정에 저장한다. 로그인 계정은 기존 설정 동기화(`axis` prefs RPC)로 서버에도 올라간다. 값이 없으면 `soft`.
- `server/notify-copy.mjs`: 앱과 같은 이벤트별·말투별 문구 표와 `notifyText(ev, vars, tone)`. 의존성이 없어 Edge Function(Deno)에서 그대로 `import` 할 수 있다.

## 서버에서 해야 할 일 (운영 변경이라 승인 후 진행)
1. 현재 푸시 스케줄러(핵심 11개 시각 계산 + 발송)가 어디 있는지 확인한다. (Supabase 대시보드 → Edge Functions / Database → Cron. 이 저장소에는 없음)
2. 발송할 때 사용자의 설정 JSON에서 `tone`을 읽는다: `toneOf(prefs)` (모르는 값은 `soft`).
3. 완성 문구를 쓰는 대신 이벤트 키로 문구를 만든다. 앱의 핵심 알림 id와 문구 키 대응은 `CORE_EV`:
   `water, sun1, move, deep1, meal1, sun2, nsdr(=카페인 마감·NSDR 합본), sun3, meal2, dim, sleep`.
   카페인 마감과 NSDR이 시각이 다르면 `caff`와 `nsdr`을 따로 보낸다.
4. 푸시 payload는 기존 형식 그대로 `{title, body, tag}`로 보낸다(서비스 워커는 이 3개만 쓴다). `tag`, 발송 시각, 중복 방지 키는 **바꾸지 않는다.**
5. 모르는 이벤트(`notifyText`가 `null`)나 `tone`을 읽지 못하는 경우는 기존 문구를 그대로 보낸다. 문구를 추측해서 바꾸지 않는다.
6. 시스템 안내(등록 실패, 권한, 계정 오류 등)는 말투 대상이 아니다.

## 함께 확인할 것 (말투와 별개로 서버가 모르는 앱 기능)
서버는 아래를 모르므로 잠금 화면 푸시는 지금도 이 내용을 반영하지 못한다. 필요하면 별도 작업이다.
- 일정 조정(`day.adj`: 미루기·당기기·건너뛰기)
- 오늘 일정 추가·반복 일정(`day.extra`, `prefs.extra`)
- 기본 루틴 편집에서 끈 항목(`prefs.tl[id].off`)과 이름 변경

## 적용 후 검증
- 말투별로 `pushTest`(테스트 알림)가 해당 말투 문구로 오는지
- 설정이 없는 계정은 `soft`로 오는지, 계정 A·B가 서로 다른 말투로 오는지
- 같은 시각 알림이 중복 발송되지 않는지(말투를 바꿔도 같은 알림이 한 번만)
